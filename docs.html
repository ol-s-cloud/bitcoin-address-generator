Browser tools

Generate a random value

  1. Open Home → Random Generator.
  2. Choose an integer, hexadecimal string, byte sequence or UUID.
  3. Set the requested length or numeric range.
  4. Select Generate random value.

The browser uses crypto.getRandomValues. Human-chosen numbers are not a safe substitute for cryptographic entropy.

Derive a legacy Bitcoin address

  1. Open Home → Bitcoin Address Lab.
  2. Generate a fresh address example, reuse the last 32-byte hexadecimal value, or enter a valid 64-character private key.
  3. Review the compressed public key, HASH160, WIF and legacy P2PKH address.
  4. Copy only the public address when sharing or checking it in a block explorer.
Keep secret: private key, WIF and recovery kit. Anyone who obtains these values may control funds associated with the address.

Address derivation

entropy → private key → secp256k1 public key → SHA-256 → RIPEMD-160 → version byte → double-SHA-256 checksum → Base58Check → P2PKH address

Command line

Use the CLI for local development and testnet-first experiments. Install from the source repository until a separately verified package release is published. 

python -m venv .venv
source .venv/bin/activate
pip install git+https://github.com/ol-s-cloud/bitcoin-address-generator.git

cobra status
cobra random --bytes 32
cobra generate
cobra validate <address> --network testnet

Private keys are hidden by default. See the CLI guide for explicit secret-output commands, network selection and current limitations.

Experimental

Offline Lab

The current Offline Lab generates a 256-bit random value using the browser cryptographic API. It does not yet include a fully packaged, dependency-free Bitcoin derivation or signing engine.

  1. Save a complete, verified COBRA offline release on the target machine.
  2. Disconnect the machine before generating secret material.
  3. Keep secrets on the offline machine; move only public addresses or verified transaction data across the boundary.

Required practice

Security boundary

  • Do not use demonstration keys for material funds.
  • Never paste a private key, seed phrase or WIF into chat, support messages, analytics, issue trackers or remote forms.
  • Confirm the Bitcoin network and address type before importing or sweeping a key.
  • Treat browser extensions, clipboard managers, screen recording, shell history and removable media as possible exposure paths.
  • Use independently reviewed wallet software or hardware for real-world custody.

Read the repository security policy ↗ before experimenting with key material.

Security note. Keep private keys, WIFs and recovery material away from shared systems, messages and analytics.
