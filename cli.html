COBRA CLI 0.3.0 · EXPERIMENTAL · TESTNET-FIRST

COBRA from
your terminal.

The CLI exposes the same cryptographic research lineage for developers who prefer command-line workflows. Version 0.3.0 is intentionally testnet-first and is not a production wallet.

Install

Until a separately verified PyPI release is published, install directly from the source repository with pip:

python -m venv .venv source .venv/bin/activate # macOS / Linux # .venv\Scripts\activate # Windows pip install git+https://github.com/ol-s-cloud/bitcoin-address-generator.git cobra --version cobra status

For an air-gapped machine, download/build the package and dependencies on a connected machine first, verify the artifacts, then transfer them offline. Do not make the offline signer fetch packages from the internet.

Commands available now

cobra status cobra random --bytes 32 cobra generate # testnet by default cobra generate --network testnet cobra derive <64-hex-private-key> --network testnet cobra validate <address> --network testnet # Explicit experimental mainnet derivation cobra generate --network mainnet
AVAILABLE

Local CSPRNG randomness, secp256k1 key derivation, legacy P2PKH address generation, testnet/mainnet network selection, checksum validation and CLI status.

NOT YET AVAILABLE

PSBT construction, transaction signing, broadcasting, HD/seed wallets, multisig orchestration, hardware-wallet integration or production custody guarantees.

Secret handling

Generated private keys are hidden by default. Developers must explicitly request terminal output with --show-secret or write locally with --secret-output. Shell history, screen recording and log capture can expose secrets.

cobra generate --network testnet --show-secret cobra generate --network testnet --secret-output ./testnet-key.txt
Security status: COBRA CLI 0.3.0 is Alpha/experimental. Use testnet or signet for development. Do not entrust material funds to the CLI until transaction functionality, reproducible builds, deterministic vectors and independent security review are complete.

Why testnet first?

Testnet lets developers exercise key/address flows without representing experimental software as custody-grade. The next terminal milestone is PSBT inspection and testnet/signet signing, followed by two-machine air-gap testing.
